# API contract

`max4live-ts-tools/core` is pure in-memory parsing, validation, editing, building, querying and diff. It has no Node filesystem imports. The root barrel additionally provides readFile/writeFile and PatchEditor.fromFile()/write(). Embedded editors returned by atPath are core editors; write their normalized snapshots with writeFile.

Editor factories take ownership through deep copies. Query results, raw output and normalized snapshots are owned copies. Revisions internally share untouched boxes, lines and metadata; simple mutations copy only containers plus changed data. Consumers cannot mutate another revision through a public value. Custom rules receive isolated snapshots at each scope and may return diagnostics; they must not throw or use side effects as control flow.

updateBox/removeBox throw BOX_NOT_FOUND. addBox rejects ID_EXISTS and invalid fields. connect requires existing boxes and safe nonnegative integer ports within counts. disconnect validates tuple shape and nonnegative integer indices, allowing removal of dangling/out-of-bounds connections; an absent connection is an identity operation. connect with existing endpoints and omitted metadata is idempotent; supplied nonempty metadata throws LINE_EXISTS instead of being silently ignored. Reducing connected ports throws CONNECTED_PORT_REMOVED. Remove cascades attached lines. Box/endpoint errors use MaxpatEditError.code; JSON/structural errors use MaxpatStructuralError. Parse/IO errors retain causes. No writes occur during validation.

Builder object() requires inlet/outlet counts, because Max objects can have arguments or dynamic ports that cannot be inferred offline. Default class is newobj, rect [0,0,80,22]; explicit IDs simplify connection composition. Attributes and variable names are ordinary preserved Max data; no runtime resolution is claimed.

Paths are arrays of containing box IDs, e.g. ["container", "child"]. IDs are local to a patcher; walkPatch yields preorder scope snapshots, queryPatch includes each path. External bpatcher filenames are preserved but never loaded. Embedded patchers are bounded to 24 scopes and JSON nesting to 128 levels (one million values); parsed text limit is 20 million UTF-16 code units (20 × 1024 × 1024); file reads additionally cap UTF-8 input at 40 MiB. Each scope allows at most 100,000 boxes and 200,000 lines. Bounds apply before serialization/Zod recursion; they are resource safeguards, not streaming support. Large editing uses map copies; repeated single-box insertion can be quadratic. Array order, unknown JSON values and negative zero are retained; whitespace and object key order are canonicalized. Comments, non-JSON values and binary amxd are unsupported.
